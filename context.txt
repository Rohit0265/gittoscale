                    GITTOSCALE — COMPREHENSIVE APPLICATION CONTEXT
================================================================================

1. OVERVIEW & PRODUCT PURPOSE
--------------------------------------------------------------------------------
GitToScale (also known as System Design Playground) is an interactive, full-stack
web application and capacity planning workbench designed for software engineers,
system architects, and engineering students.

Unlike static diagramming tools (draw.io, Lucidchart) or resource-heavy black-box
load testing tools, GitToScale bridges the gap between architectural modeling and
runtime verification:
- It allows users to visually design distributed systems on a reactive canvas.
- It runs an instant, deterministic analytical traffic simulator (modeling DAG
  rate propagation, M/M/m/K queuing dynamics, and latency estimation) to catch
  bottlenecks and cascading failures before code reaches production.
- It automatically extracts architecture topologies from real-world GitHub
  repositories by parsing dependency manifests and source files.
- It embeds an AI System Design Architect copilot powered by LLMs (e.g. Gemini)
  to translate natural-language requirements into editable canvas topologies.
- It features a community feed where developers share interactive architectures,
  publish design RFCs, discuss trade-offs, and open shared diagrams directly in
  their own canvas.

Live URL: https://www.gittoscale.tech (or https://gittoscale.tech)

3. COMPLETE FEATURE BREAKDOWN (WHAT, WHERE, HOW)
================================================================================

--------------------------------------------------------------------------------
FEATURE 1: DETERMINISTIC ANALYTICAL TRAFFIC SIMULATOR
--------------------------------------------------------------------------------
WHAT IT DOES:
  Simulates high-throughput traffic through a distributed microservices DAG.
  Calculates incoming arrival rate (lambda), service rate (mu), worker capacity,
  utilization percentage, queue accumulation, request drop rates, and latency
  degradation for each node without running real servers. Identifies and ranks
  constrained components and service bottlenecks in real time.

WHERE IT LIVES:
  - Backend Engine:
    • backend/src/simulation/engine.ts        -> Topological sort (Kahn's algorithm),
                                                DAG rate propagation, bottleneck ranking.
    • backend/src/simulation/queue.ts         -> M/M/m/K queuing dynamics and drop policies.
    • backend/src/simulation/latency.ts       -> Baseline latency + queuing delay model.
    • backend/src/simulation/validation.ts    -> Cycle detection (DAG check) & Zod schemas.
    • backend/src/simulation/types.ts         -> Core TypeScript types for simulation.
    • backend/src/routes/simulate.ts          -> POST /api/simulate endpoint.
  - Frontend Components:
    • frontend/src/components/RightSidebar.tsx     -> Controls sidebar showing simulation runs.
    • frontend/src/components/BottleneckList.tsx   -> Ranked list of overloaded services.
    • frontend/src/components/MetricsStrip.tsx     -> Top-level throughput/latency counters.
    • frontend/src/components/BaselineComparisonModal.tsx -> Compares current vs. snapshot setups.

HOW IT WORKS:
  1. Validates that the active graph is acyclic (detects cycles before simulation).
  2. Runs Kahn's algorithm to establish a deterministic topological execution order.
  3. Propagates traffic: root load generators output their configured request rate;
     downstream nodes receive the sum of upstream completed traffic multiplied by
     edge call multipliers (e.g. 1 frontend request triggers 3 DB queries).
  4. Calculates effective capacity: capacityPerSecond * workerCount.
  5. Computes queue saturation and drops based on node overflow policies (reject vs drop).
  6. Estimates latency: baseline processing time combined with queueing delay.

FEATURE 2: INTERACTIVE REACT FLOW CANVAS & COMPONENT INSPECTOR
--------------------------------------------------------------------------------
WHAT IT DOES:
  Provides a drag-and-drop visual canvas for assembling architectures. Features
  custom nodes (Load Generator, API Gateway, Microservice, Cache, Database),
  dynamic bezier edges with traffic rate badges, live status indicators
  (Normal, Warning, Overloaded, Disabled), full pan/zoom/fit controls, and a
  property inspector to fine-tune capacities.

WHERE IT LIVES:
  - frontend/src/components/Canvas/ArchitectureCanvas.tsx -> Core React Flow wrapper,
                                                            listeners, viewport controls.
  - frontend/src/components/Canvas/CustomNodes.tsx        -> Custom node component rendering
                                                            icons, health badges, metrics.
  - frontend/src/components/Canvas/CustomEdge.tsx         -> Animated bezier edge with call
                                                            multipliers and flow badges.
  - frontend/src/components/ComponentInspector.tsx        -> Property editor for worker counts,
                                                            capacity/s, latency, queues.
  - frontend/src/components/ComponentsListCard.tsx        -> Hierarchical tree of components.
  - frontend/src/utils/detailedArchitecture.ts            -> Toggles between Basic View (services)
                                                            and Detailed View (controllers/DBs).

HOW IT WORKS:
  - Custom nodes display live status badges dynamically updated based on simulation
    results: Green (Normal: <80% util), Amber (Warning: >=80% util), Red (Overloaded:
    util > 100% or queue overflow), Slate (Disabled).
  - Component Inspector allows editing worker count, capacity per second, baseline
    latency, queue max size, and overflow behavior. Edits trigger debounced re-simulation.

FEATURE 3: GITHUB REPOSITORY SCANNER & AUTO-TOPOLOGY BUILDER
--------------------------------------------------------------------------------
WHAT IT DOES:
  Ingests public GitHub repositories or local directories, scans file trees,
  analyzes dependency manifests and source files, detects services, background
  workers, databases, caches, and queues, and automatically synthesizes an
  interactive architecture diagram on the canvas.

WHERE IT LIVES:
  - Backend Scanner:
    • backend/src/services/githubScanner.ts    -> GitHub REST API tree fetcher & manifest loader.
    • backend/src/services/staticScanner.ts    -> Static analysis engine recognizing Express,
                                                 NestJS, Fastify, Go Gin, Actix, Spring,
                                                 BullMQ, Kafka, Redis, Postgres, MongoDB, etc.
    • backend/src/services/repoAnalysisTypes.ts-> Types for inventory, items, candidate roles.
    • backend/src/routes/repository.ts         -> POST /api/repository/scan endpoint.
  - Frontend UI:
    • frontend/src/components/RepositoryImportModal.tsx -> Modal for GitHub URL input,
                                                          token option, and scanning progress.

HOW IT WORKS:
  1. User enters a GitHub URL (e.g. https://github.com/owner/repo).
  2. Backend queries GitHub Git Trees API recursively for file manifests
     (package.json, go.mod, Cargo.toml, requirements.txt, pom.xml, Dockerfile,
     docker-compose.yml).
  3. Static scanner detects framework signatures and database connectors to classify
     components into Gateway, Service, Database, Cache, or Queue.
  4. Generates nodes and wires directional edges, applying an automatic tree layout
     (treeLayout.ts) to position them cleanly on the canvas.


--------------------------------------------------------------------------------
FEATURE 4: AI SYSTEM DESIGN ARCHITECT & IN-CANVAS COPILOT
--------------------------------------------------------------------------------
WHAT IT DOES:
  An intelligent assistant powered by LLMs (e.g. Google Gemini) that creates,
  refines, and explains system architectures. Operates in two primary modes:
  1. Full System Design Architect wizard (generates comprehensive architectural
     reports, capacity estimations, and Mermaid diagrams).
  2. Live In-Canvas Copilot (conversational chat embedded in the canvas sidebar
     that executes real-time mutations like adding nodes, scaling fleets, or wiring caches).

WHERE IT LIVES:
  - Backend Services:
    • backend/src/services/aiSystemDesignArchitect.ts -> Prompt engineering & report generator
                                                        for Modes A (Repo), B (Prompt), C (Scale).
    • backend/src/services/aiChatService.ts           -> Live chat prompt builder that injects
                                                        active canvas nodes, edges & bottlenecks.
    • backend/src/routes/recommend.ts                 -> POST /api/recommend endpoint.
    • backend/src/routes/chat.ts                      -> POST /api/chat and /api/chat/stream.
  - Frontend Services & UI:
    • frontend/src/components/ProjectWorkspace/ContextualQuerySidebar.tsx -> Chat panel beside canvas.
    • frontend/src/components/ArchitectureRecommender/ArchitectureRecommenderPage.tsx -> Full wizard page.
    • frontend/src/services/aiAgentExecutor.ts        -> Client-side command executor parsing AI
                                                        intent and applying mutations directly to canvas.
    • frontend/src/utils/exportDiagram.ts             -> Parses Mermaid diagram syntax into
                                                        React Flow nodes and edges.

HOW IT WORKS:
  - In chat, the user can say "Add a Redis cache before the Database" or "Scale order
    service to 5 workers". The backend receives current canvas state, generates the
    response, and the client executor automatically splices the node and recalculates
    positions.

FEATURE 5: DEVELOPER COMMUNITY FEED & COLLABORATIVE DESIGN HUB
--------------------------------------------------------------------------------
WHAT IT DOES:
  A full social and developer knowledge hub where users publish their architecture
  designs, write RFCs/articles in Markdown, upload images and videos, comment in
  threaded discussions, like/dislike, bookmark posts, and follow other engineers.
  Any shared architecture in a post can be opened directly into the viewer's canvas
  with 1 click ("Open in Canvas").

WHERE IT LIVES:
  - Backend Feed Service:
    • backend/src/feed/feedRoutes.ts         -> REST API endpoints for feed, posts, comments,
                                                reactions, bookmarks, follows, and uploads.
    • backend/src/feed/feedService.ts        -> Database CRUD operations against Neon/Postgres
                                                with in-memory fallback buffers.
    • backend/src/feed/types.ts              -> FeedPost, Comment, Profile, Media item interfaces.
    • backend/src/services/mediaCompressionService.ts -> Sharp image resizing and optimization.
    • backend/src/services/r2Service.ts      -> Cloudflare R2 S3-client upload and delete handler.
  - Frontend Feed Pages & Components:
    • frontend/src/feed/pages/FeedPage.tsx             -> Main feed view with trending/recent tabs.
    • frontend/src/feed/pages/ProfilePage.tsx          -> Public user profile with bio & posts.
    • frontend/src/feed/components/CreatePost.tsx      -> Post composer with Markdown & media drop.
    • frontend/src/feed/components/RichPostInput.tsx   -> Rich text formatting controls.
    • frontend/src/feed/components/PostCard.tsx        -> Feed card previewing diagram & stats.
    • frontend/src/feed/components/CommentPanel.tsx    -> Threaded replies and discussions.
    • frontend/src/feed/components/PostMediaGallery.tsx-> Media layout prioritizing video first.
    • frontend/src/feed/components/EditProfileModal.tsx-> Profile editor (bio, social links, avatar).

HOW IT WORKS:
  - When creating a post from the playground, the current canvas nodes and edges are
    attached as JSON.
  - When media is uploaded, the backend compresses images using Sharp to prevent bloat
    and stores them in Cloudflare R2 (or local fallback disk), returning a CDN URL.
  - Videos are automatically prioritized to appear first in media carousels.

--------------------------------------------------------------------------------
FEATURE 7: AUTHENTICATION, USER PROFILES & SECURITY
--------------------------------------------------------------------------------
WHAT IT DOES:
  Provides secure authentication supporting Email/Password, GitHub OAuth, and
  Google OAuth. Uses Row-Level Security (RLS) in PostgreSQL so users can only
  modify their own projects. Handles cross-domain storage and resumes pending
  actions after login (e.g. if an unauthenticated user enters a prompt on the
  landing page, they are routed to sign up and the prompt executes immediately
  upon login).

WHERE IT LIVES:
  - Frontend Auth:
    • frontend/src/contexts/AuthContext.tsx            -> User session state & token management.
    • frontend/src/components/ui/modern-login-signup.tsx -> Clean, animated modal for login/signup.
    • frontend/src/components/auth/AuthCallback.tsx    -> OAuth callback and popup handler.
    • frontend/src/components/auth/ForgotPasswordPage.tsx -> Password reset flow.
    • frontend/src/utils/oauthHelper.ts                -> Popup vs redirect detection.
  - Backend Auth:
    • backend/src/middleware/auth.ts                   -> JWT verification middleware.
    • backend/src/routes/auth.ts                       -> User profile sync on sign-in.
    • backend/src/utils/ssrfGuard.ts                   -> SSRF security protection for outbound URLs.

4. DATABASE SCHEMA & DATA MODEL (POSTGRESQL / SUPABASE)
================================================================================

All tables are defined in supabase/migrations/ and enforced via PostgreSQL RLS:

1. public.profiles
   - id: UUID (references auth.users)
   - full_name: TEXT
   - email: TEXT
   - avatar_url: TEXT
   - bio: TEXT
   - role: TEXT (e.g. "Software Engineer")
   - company: TEXT
   - github_username: TEXT
   - twitter_username: TEXT
   - website: TEXT
   - created_at / updated_at: TIMESTAMPTZ

2. public.architecture_history
   - id: UUID (Primary Key)
   - user_id: UUID (References auth.users)
   - title: TEXT
   - prompt: TEXT
   - generation_config: JSONB (traffic parameters, duration, model)
   - architecture_data: JSONB (nodes array, edges array, canvas settings)
   - status: TEXT ('completed', 'failed', 'generating')
   - error_message: TEXT

3. public.repository_history
   - id: UUID (Primary Key)
   - user_id: UUID (References auth.users)
   - repository_url: TEXT
   - owner / repo_name / default_branch / commit_sha: TEXT
   - summary: TEXT
   - inventory: JSONB (scanned file manifests and classifications)
   - architecture_data: JSONB (generated nodes and edges)
   - status: TEXT

4. public.feed_posts
   - id: UUID (Primary Key)
   - user_id: UUID (References auth.users)
   - title: TEXT
   - description: TEXT
   - content_markdown: TEXT
   - architecture_data: JSONB (canvas nodes & edges snapshot)
   - media_url: TEXT (primary media URL)
   - media_type: TEXT ('image' or 'video')
   - media_items: JSONB (array of media URLs and Cloudflare R2 keys)
   - media_metadata: JSONB
   - view_count: INTEGER
   - is_pinned: BOOLEAN

5. public.feed_comments
   - id: UUID (Primary Key)
   - post_id: UUID (References feed_posts)
   - user_id: UUID (References auth.users)
   - parent_id: UUID (Self-reference for nested threaded replies)
   - content: TEXT

6. Social Interaction Tables:
   - public.feed_likes      (post_id, user_id, created_at)
   - public.feed_dislikes   (post_id, user_id, created_at)
   - public.feed_bookmarks  (post_id, user_id, created_at)
   - public.feed_follows    (follower_id, following_id, created_at)

  GET  /api/history/architectures      -> Fetches saved architecture list

  GET    /api/feed/posts               -> Lists community posts (supports pagination & sorting)
